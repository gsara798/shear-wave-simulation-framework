# Source assembly V2 — implemented independent of synthesis

The new call `bundle = swsynth.sources.prepare(request)` creates **physical source data**, without generating wave propagation directions or tissue polarization.

## Input (new API)

```matlab
request=struct();
request.geometry="2d";                % or projected3d / volumetric3d
request.count=2;                      % physical emitters, not wave components
request.positions=struct("method","explicit", ...
    "position_xyz_m",[.01 0 .02;.03 0 .04]);
request.excitation=struct( ...
    "force_direction_xz",[1 0;0 1], ...
    "relative_amplitude",[1;1], ...
    "phase_rad",[0;pi]);
% Omit aperture for point sources, or set a coherent line aperture:
request.aperture=struct("model","line_segment", ...
    "span_m",.002,"axis_xyz",[1 0 0], ...
    "node_spacing_m",.001);
bundle=swsynth.sources.prepare(request);
```

`geometry="2d"` normalizes to `"planar2d"`; only planar force/positions/aperture elements are accepted. Sources can be off the observation plane when `geometry="projected3d"`. Source count is not wave-component count.

`request.positions` is passed to the independent `sources.positions.generate` contract: `explicit`, `fibonacci`, or `random`; nested geometry/count are optional but **must match** the parent if supplied. `request.excitation` is passed to `sources.excitation.generate`: fixed/random forces, amplitudes, phases. `request.observation_y_m` sets the plane of 2D positions and aperture nodes (default zero).

`request.aperture` can be one shared definition (scalar struct) or 1-by-N definitions for the N physical sources. Omitted aperture means point emitters. Models: `point`, `line_segment`. The existing geometric kernel `swsynth.sources.buildCoherentAperture` is reused for each source; unsupported configurations are rejected.

Optional independent random streams:

```matlab
request.streams.positions=RandStream("mt19937ar","Seed",101);
request.streams.excitation=RandStream("mt19937ar","Seed",202);
bundle=swsynth.sources.prepare(request);
```

The streams are **caller supplied**; there is no silent global reseeding. Without explicit streams, random position/excitation modules use MATLAB's current global RNG. In this stage the excitation generator itself uses one stream sequentially for force/amplitude/phase; finer-grained substreams will be addressed separately. Supplying a stream both in a nested request and in `request.streams` is rejected.

## Output

```matlab
bundle.geometry                          % normalized spatial geometry
bundle.count                             % number of PHYSICAL sources
bundle.sources.source_id                 % [1;...;N]
bundle.sources.position_xyz_m            % N x 3, metres
bundle.sources.force_direction_xyz       % N x 3, unit force directions
bundle.sources.relative_amplitude        % N x 1, nonnegative
bundle.sources.phase_rad                 % N x 1, initial phase
bundle.sources.aperture                  % 1 x N geometric descriptions
bundle.excitation                        % independently validated excitation
bundle.aperture.per_source               % 1 x N geometry/weight metadata
bundle.aperture.node_xyz_m               % M x 3 flattened emitting nodes
bundle.aperture.node_source_id           % M x 1 physical source index
bundle.aperture.node_weight              % M x 1 coherent element weights
bundle.aperture.node_count_per_source    % N x 1
```

**Coherence:** aperture nodes inherit the *parent source's* initial phase, amplitude, and force direction; each source's aperture weights are nonnegative and sum to one. **No additional independent phases are sampled per aperture node.** The wave synthesizer is responsible for applying the source-level excitation at every node using `node_source_id`, then computing propagation and radiation physics. No propagation field is generated by `sources.prepare`.

Each source can have a different number of aperture nodes. The flattened node table plus `node_source_id` is preferable to forcing a single fixed N-by-K-by-3 array.

## Legacy compatibility and migration

The existing two-argument call remains supported without changing its numerical behavior:

```matlab
legacySources=swsynth.sources.prepare(cfg,directions);
```

Its former implementation lives at `swsynth.sources.compat.prepareLegacy` and preserves old single-precision sampling, RNG consumption, and output fields. The **one-argument form is the V2 contract**.

No existing synthesizer is switched to the new assembled bundle yet. Do not assume a new `sources.prepare(request)` request is accepted by `swsynth.run(cfg)`. Integrate through end-to-end field and RNG regression tests before replacing legacy paths.
